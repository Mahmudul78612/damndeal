PURPOSE OF THIS DOCUMENT
------------------------
This is the single source of truth for the Road Hustlers backend. It describes
EVERY entity, role, workflow and API endpoint so that frontend developers can
build the Customer Website AND the ERP/Admin portal WITHOUT designing anything
on the backend side. If it is in this document, the API will provide it.

The system is ONE backend serving TWO frontends:
  1. CUSTOMER WEBSITE  — public marketing site + logged-in customer area
  2. ERP / ADMIN PORTAL — internal garage management (staff + owner)


═══════════════════════════════════════════════════════════════════════════════
  1. SYSTEM ARCHITECTURE
═══════════════════════════════════════════════════════════════════════════════

  ┌──────────────────────┐        ┌──────────────────────┐
  │  CUSTOMER WEBSITE     │        │   ERP / ADMIN PORTAL  │
  │  (public + customer)  │        │   (staff + owner)     │
  └──────────┬───────────┘        └───────────┬──────────┘
             │                                 │
             │      HTTPS / REST JSON          │
             └──────────────┬──────────────────┘
                            │
                  ┌─────────▼──────────┐
                  │   ROAD HUSTLERS     │
                  │   BACKEND API       │   Node.js + Express
                  │   /api/...          │   JWT auth (access+refresh)
                  └─────────┬──────────┘
                            │
                  ┌─────────▼──────────┐
                  │   MongoDB           │   primary data store
                  │   (+ file uploads)  │   /uploads for images/PDF
                  └────────────────────┘

  Auth model:
    - JWT access token (15 min) + refresh token (30 days)
    - Role baked into token: "customer" | "staff" | "manager" | "admin"
    - Header on every request:  Authorization: Bearer <token>
    - x-client-type: "website" | "erp"   (lets backend scope behavior)

  Base URL:    https://road-hustlers.com/api
  Money:       all amounts are USD, stored in cents OR 2-decimal numbers (cents
               recommended to avoid float errors). Display as $1,234.56.
  Dates:       ISO-8601 UTC strings.
  IDs:         Mongo ObjectId strings.

═══════════════════════════════════════════════════════════════════════════════
  4. END-TO-END WORKFLOWS
═══════════════════════════════════════════════════════════════════════════════

───────────────────────────────────────────────────────────────────────────────
WORKFLOW A — WEBSITE VISITOR BECOMES A PAYING CUSTOMER
───────────────────────────────────────────────────────────────────────────────
  1. Visitor lands on road-hustlers.com (public, no login).
  2. Fills "Request a Quote / Book Service" form.
       → POST /api/website/leads        creates LEAD (status=new)
       → notification fires to advisors.
  3. Advisor sees lead in ERP → Leads board → calls/emails customer.
       → PATCH /api/erp/leads/:id  (status=contacted, notes)
  4. Advisor books an appointment.
       → POST /api/erp/appointments    (status=confirmed)
       → optionally converts lead → Customer + Vehicle.
  5. Customer arrives. Advisor opens a WORK ORDER (job card).
       → POST /api/erp/work-orders     (status=estimate)
  6. Technician inspects, adds diagnosis + labor + parts lines.
       → PATCH /api/erp/work-orders/:id
  7. System builds an ESTIMATE total. Advisor sends it.
       → POST /api/erp/work-orders/:id/send-estimate  (email link to customer)
  8. Customer approves (portal, email link, or verbally).
       → POST /api/website/work-orders/:id/approve   (customer portal)
         or POST /api/erp/work-orders/:id/approve     (advisor records approval)
       → status = approved.
  9. Tech clocks in, does the work, clocks out (time log).
       → POST /api/erp/work-orders/:id/clock-in / clock-out
       → status = in_progress → completed.
 10. Parts used are deducted from inventory automatically.
 11. Advisor generates INVOICE from the work order.
       → POST /api/erp/work-orders/:id/invoice   creates INVOICE + PDF.
 12. Invoice emailed to customer.
       → POST /api/erp/invoices/:id/send
 13. Customer pays (in shop or online via Stripe).
       → POST /api/erp/invoices/:id/payments        (in-shop)
       → POST /api/website/invoices/:id/pay          (online Stripe)
       → status = paid. totalSpent updated. job closed.

───────────────────────────────────────────────────────────────────────────────
WORKFLOW B — INVENTORY / PARTS LIFECYCLE
───────────────────────────────────────────────────────────────────────────────
  1. Admin/manager adds parts to catalog with cost, sell price, stock, reorder level.
  2. When stock < reorderLevel → low-stock notification + appears on dashboard.
  3. Manager creates a PURCHASE ORDER to a supplier.
       → POST /api/erp/purchase-orders (status=draft → ordered)
  4. Parts arrive → mark received.
       → POST /api/erp/purchase-orders/:id/receive
       → stock auto-incremented.
  5. Parts consumed by work orders auto-decrement stock on invoice.
  6. Inventory valuation + low-stock report available in analytics.

───────────────────────────────────────────────────────────────────────────────
WORKFLOW C — CUSTOMER PORTAL (logged-in website area)
───────────────────────────────────────────────────────────────────────────────
  - Register / login with email + password.
  - View profile + edit contact info.
  - See "My Vehicles" with full service history.
  - See estimates awaiting approval → approve/decline.
  - See invoices → download PDF → pay online.
  - Book a new appointment.
  - Message/notes thread with the shop (optional phase 2).

───────────────────────────────────────────────────────────────────────────────
WORKFLOW D — STAFF / TECHNICIAN DAY
───────────────────────────────────────────────────────────────────────────────
  - Login to ERP (role=staff).
  - See "My Jobs" (work orders assigned to me) for today.
  - Open a job → add diagnosis, labor hours, parts used, photos.
  - Clock in / clock out per job (time tracking → payroll + productivity).
  - Mark job completed → advisor takes over for invoicing.

───────────────────────────────────────────────────────────────────────────────
WORKFLOW E — OWNER / ANALYTICS
───────────────────────────────────────────────────────────────────────────────
  Dashboard KPIs (all USD):
    - Revenue today / week / month / YTD
    - Open work orders by status
    - Outstanding (unpaid) invoices total
    - Jobs completed count + average ticket size
    - Parts profit (sell - cost) & labor revenue split
    - Technician productivity (billable hours, jobs done)
    - Lead funnel (new → converted) & conversion rate
    - Low-stock parts list
    - Top services & top-spending customers

  6. MONEY / CALCULATION RULES (USD)
═══════════════════════════════════════════════════════════════════════════════
  laborLineTotal   = hours × rate            (or flatPrice if set)
  partLineTotal    = quantity × sellPrice
  laborSubtotal    = Σ laborLineTotals
  partsSubtotal    = Σ partLineTotals
  subtotal         = laborSubtotal + partsSubtotal
  discountAmount   = fixed $ or (subtotal × discount%)
  taxableBase      = subtotal − discountAmount      (parts usually taxable;
                                                     labor taxability varies by
                                                     state — configurable)
  taxAmount        = taxableBase × (taxRate/100)
  shopSuppliesFee  = min(laborSubtotal × fee%, cap)
  grandTotal       = subtotal − discountAmount + taxAmount + shopSuppliesFee
  amountDue        = grandTotal − amountPaid

  Store cents internally; round only at display.
