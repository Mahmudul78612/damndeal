DamnDeal Ads — Integration

Self-hosted ad network with geo-targeting, click tracking, and conversion (sale) tracking like Meta Pixel / Google Conversion Tracking.

API Base   https://damndeal.in/ads/api
Admin portal   https://damndeal.in/ads/admin/
Advertiser portal   https://damndeal.in/ads/portal/
Embed SDK   https://damndeal.in/ads/embed.js
Conversion pixel   https://damndeal.in/ads/event.js

All responses are JSON: { success: true, ... } or { success:false, message }.

1. Show ads — Embed SDK easiest

Renders a full ad unit (creative + headline + CTA button) automatically — like Google AdSense.

<!-- where the ad should appear -->
<div class="dd-ad" data-zone="YOUR_ZONE_KEY" data-app="damndeal"></div>

<!-- once, near </body> -->
<script src="https://damndeal.in/ads/embed.js" async></script>
  • Get YOUR_ZONE_KEY from Admin portal → Zones.
  • Viewer location auto-detected from IP (state-wise targeting).
  • No ad? The slot hides itself. SPA: call DDAds.refresh() after navigation.

2. Show ads — Serve API custom design

GET https://damndeal.in/ads/api/serve?zone=ZONE_KEY&app=damndeal

Override geo for server-side calls: &ip=1.2.3.4 or &country=IN&state=MH.

{
  "success": true,
  "ad": {
    "id":"...", "type":"banner", "title":"Summer Sale 50% Off",
    "creativeUrl":"https://damndeal.in/ads/uploads/ads/x.jpg",
    "width":320, "height":50, "cta":"Shop Now",
    "clickUrl":"https://damndeal.in/ads/api/click/?zone=...&app=..."
  },
  "location": { "country":"IN", "state":"MH", "city":"Mumbai" }
}

"ad": null → no match, render nothing. Render with the tracked clickUrl:

<a href="${ad.clickUrl}" target="_blank">
  <img src="${ad.creativeUrl}" width="${ad.width}" height="${ad.height}">
</a>
<button onclick="location.href='${ad.clickUrl}'">${ad.cta}</button>
Calling /serve logs one impression. Opening clickUrl logs one click and 302-redirects to the advertiser's site.

3. Track sales — how attribution works ⭐ Event Manager

  1. A user clicks an ad. Our clickUrl redirects to the advertiser site and automatically appends ?dd_click=<id>.
  2. The advertiser site remembers that id (30 days).
  3. On purchase/signup, the site fires a conversion event with that id → we attribute the sale to the exact ad.

Two ways to send conversions — use either or both:

3A. Browser Pixel (like Meta Pixel)

Step 1 — on every page:

<script src="https://damndeal.in/ads/event.js"></script>

Step 2 — on the order-success / thank-you page:

<script>
  ddq('purchase', { value: 1299, currency: 'USD', orderId: 'ORD-12345' });
</script>

More events:

ddq('lead');                                  // form lead
ddq('signup', { value: 0 });                  // registration
ddq('add_to_cart', { value: 499 });
ddq('purchase', { value: 2599, orderId: 'INV-9' });

3B. Server-side Conversions API (like Meta CAPI)

Reliable server-to-server. Each advertiser has a Conversion API Key (ddc_...) shown in their portal & in the admin onboarding pack.

POST https://damndeal.in/ads/api/event
Content-Type: application/json
x-api-key: ddc_your_advertiser_key

{ "event":"purchase", "value":1299, "currency":"USD", "orderId":"ORD-12345" }
curl -X POST https://damndeal.in/ads/api/event \
  -H "Content-Type: application/json" \
  -H "x-api-key: ddc_your_advertiser_key" \
  -d '{"event":"purchase","value":1299,"orderId":"ORD-12345"}'

Event API — reference

FieldWhereNotes
eventbody/querypurchase · lead · signup · add_to_cart · custom. default purchase
valuebody/querysale amount. default 0
currencybody/querydefault USD
orderIdbody/querydedupe key per advertiser — recommended
clickIdbody/querydd_click value — best attribution
x-api-keyheaderadvertiser key (server-side)
zonebody/queryfallback attribution

Responses:

{ "success": true,  "message": "Conversion recorded", "value": 1299 }
{ "success": true,  "deduped": true, "message": "Duplicate order ignored" }
{ "success": false, "message": "Could not attribute event (no matching click)" }
Attribution priority: clickId (exact) → x-api-key + same-IP recent click → zone + same-IP recent impression.

The advertiser then sees the full funnel in their portal: Impressions → Clicks → CTR → Conversions → Sale Value, state-wise.

4. Portal / Admin API

Login returns a JWT. Send Authorization: Bearer <accessToken> on protected calls.

POST /api/auth/login   { email, password }   // header x-client-type: admin | advertiser
POST /api/auth/refresh-token  { refreshToken }
GET  /api/auth/me

Admin /api/admin

MethodPathPurpose
GET/POST/PUT/DELETE/admin/adsmanage ads (POST = multipart upload)
GET/POST/PUT/DELETE/admin/advertisersadvertiser accounts
POST/admin/advertisers/:id/regenerate-keyrotate API key
GET/POST/PUT/DELETE/admin/zonesplacements (each has apiKey)
GET/admin/analytics/overviewKPIs incl. conversions

Advertiser /api/advertiser

GET /advertiser/me                  // includes your apiKey
GET /advertiser/ads
GET /advertiser/analytics/overview  // impressions, clicks, conversions, sale value
GET /advertiser/analytics/ads/:id   // trend + state-wise + conversions

5. Advertiser cheat-sheet

Hand this to a company you onboard:

  1. We give you a portal login + your Conversion API Key.
  2. Put <script src="https://damndeal.in/ads/event.js"></script> on every page.
  3. On your success page: ddq('purchase', { value: <amount>, orderId: '<id>' });
  4. Log in at https://damndeal.in/ads/portal/ → see impressions, clicks, conversions & sale value, state-wise.
